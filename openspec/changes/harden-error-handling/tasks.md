## 1. Prove the bugs and record a baseline

- [ ] 1.1 Add `packages/core/tests/errors.spec.ts` with one test per item below. Each asserts the intended behavior and must fail on the current source with an assertion about wrong state or counts (not a syntax or import error). The handler arrives in group 2, so these avoid `setErrorHandler`; the reporting assertions are in 1.2. A derived throw leaks the tracking globals today (E6), so reset them after each test (`setRunningComputation(null)`, `setCurrentContext(null)`, `setContextIndex(0)`) or the leak spills into the next test. Record the failing test names in this task.
  - E1: an effect that throws once runs again when a source it read changes (batched and unbatched).
  - E2: an effect over a derived that throws once recovers when the derived succeeds.
  - E3: a sibling effect still runs in the same flush as a thrower (inside and outside a batch).
  - E4: an effect that writes a signal stays alive when another effect throws in the nested flush.
  - E6: after a top-level derived throw, `getRunningComputation()` is `null`. Do not assert that a later top-level read is not tracked by the derived: that already holds today (the stray read lands in the leaked global context, never in the derived's `_sources`), so it cannot detect the bug.
  - E7, later-run shape: an effect reads `s`, then `d` inside `try/catch` (`d` reads `hidden` and throws when `s === 2`), then `other`. After `s.value = 2`, changing `hidden` re-runs the effect. It fails today because `d` stays DIRTY after the throw, so its next mark is a no-op (I1); the effect is still linked to `d`. Changing `other` already re-runs the effect today, so assert it as a guard, not as part of the failing test.
  - E7b, first-run shape: the same effect, but `d` throws on the effect's first run. Afterwards the effect's sources are `[s, d, other]` and changing `s` re-runs it. Today the effect ends up with sources `[hidden, other]`: it takes `d`'s reads as its own and loses `s` and `d` (I3).
  - E11, I3 inside a derived: a derived that reads `a`, then a throwing derived inside `try/catch`, then `b`, has sources `[a, inner, b]`. Today it has only `[b]`.
  - E9: a `when` with `final: true` whose callback throws is disposed, and its source has no observers afterwards.
  - E13, disposing twice: a second call to an effect's disposer does nothing, so the cleanup function runs once. Today it runs again. (The strip plugin in `packages/core/vite.config.ts` removes `assert` in tests and builds, so the second dispose does not throw there; only unstripped source throws `item must be in the array`.)
